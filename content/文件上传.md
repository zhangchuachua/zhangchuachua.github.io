- Q: 当 `input type="file"` 选中了一个文件的时候，浏览器回去读取文件的二进制数据吗？
- A：不会
- Q：如果使用 createObjectURL 呢？
- A：使用 createObjectURL 会创建一个对文件(假设是图片)的 blob 引用，如果不使用这个引用那么就不会去读取。但是如果在 img 中使用了这个 url 那么浏览器就回去读取。并且 blob 是按需分块读取的，不会一下全部读取，所以如果有一个非常大的数据，也不会卡死线程。

- Q：input 如何限制文件
- A：可以使用 accept 属性，比如 `accecpt="image/*,.pdf"` 表示接受所有图片和 pdf 文件，当然如果想要自定义限制文件，那么可以使用 onChange 自定义设置。

- Q：input 如何选择多个文件？
- A：只需要添加 multiple 属性即可。

- Q：如何追加文件？
- A：可以使用两个 input，第一个 input 用于存储已经选择的，第二个 input 用于追加文件，点击追加按钮时，调用第二个 input 的 click；然后将两个 FileList 合并，重新复制给第一个input 的 files。最后重置第二个 input。

> [!tip] FileList
> 选中一个文件时，input.value.files 将会有值，值的类型是 FileList 是一个对象，使用 FileList 循环里面的文件。
> 
> 如果直接修改 FileList 里面的文件，是不起作用的，比如 `FileList[0] = undefined` 虽然不会报错，但是再次打印 FileList 会发现值没有任何变化。

- Q：上面说 FileList 是不能直接修改的，那么如果想要过滤 FileList 里面的部分文件应该怎么做？
- A：使用 DataTransfer 请见下面代码：

```js
export function createFileList(files: File[]) {  
  const dataTransfer = new DataTransfer()  
  
  files.forEach((file) => {  
    dataTransfer.items.add(file)  
  })  
  
  return dataTransfer.files  // DataTransfer.files 的类型就是 FileList
}

input.files = createFileList(files);
```

- Q: 如何上传文件？
- A：上传文件需要使用 FormData，请见下面代码

```js
const formData = new FormData();
files.forEach(file => { formData.append('img', file) })// 这里是将 file 都放到了 img 下面，可以使用 fromData.getAll('img') 获取所有的 图片

fetch('/upload', { method: 'post', body: formData, headers: { 'Content-Type': "multipart/form-data" } })
```

> [!tip] 拖拽上传
> input 是不支持拖拽上传的，所以需要创建另外的元素来实现这个功能，比如可以使用一个 div；
> 
> 首先，当拖拽 pdf 或者 img 等文件到浏览器时，浏览器会有默认行为，将会默认打开浏览文件，要禁止这样的默认行为需要为其绑定 drop 和 dragover 事件；
> 
> drop 将会在文件丢下时触发， dragover 事件，如果拖拽到了元素里面，那么就会一直触发（没有移动鼠标也一直触发），要禁止浏览器的默认行为就必须在这两个事件里面执行 `e.preventEvent()` 才行。
> 
> 然后，因为文件丢下时触发 drop ，所以在 drop 中写对应的逻辑就行。
> 
> 可以在 drop 的事件处理函数中，使用 e.dataTransfer.files 拿到丢下的文件。

> [!tip] 断点续传 + 秒传
> 这两个功能都需要后端支持才行。
> 
> 无论是断点续传，还是秒传，都需要先对文件进行切片处理，切片其实非常简单，因为 File 类型继承了 Blob ，而 Blob 实现了 slice 方法，使用这个方法就可以进行切片：`file.slice(start, end)` 
> 
> 假设大文件的大小是 1G, 然后每个切片是 1mb 大小，所以切片就是： `file.slice(index * 1024 * 1000, (index + 1) * 1024 * 1000)` 其中的 index 是切片的索引，什么时候结束呢？ `chunk = file.slice(start, end)` 当 chunk 等于 0 的时候就可以结束了，此时已经切完了。
> 
> 除了对文件进行切片外，还需要计算文件的 hash 值，因为 hash 作为文件的唯一标识符，可以在上传的时候先去请求判断这个文件在服务器端是否已经存在，如果存在的话，那么就可以通知上传成功，这就是「**秒传**」： `fetch('/upload/exist', { method: 'post', body: { hash } })` 
> 
> 如果只是部分切片上传成功了，那么服务器端应该返回上传成功的切片的 id，这样前端在上传的时候就直接跳过已经上传成功的切片，这就是「**断点续传**」。
> 
> 所有文件上传后，需要发起一个 merge 请求，让服务器端把切片进行合并，合并成一个大文件，
> 
> 注意：切片可能会比较耗时，比如一个 10G 的文件，切成 1MB 的大小，那么就会有 1w 个切片，所以切片这部分要进行优化的话，可以在 webWorker 或者使用 wasm 进行切片。
> 
> 注意：上传切片时，可以使用并发上传，如果切片数量不是太多的话可以使用 Promise.all 但是如果切片数量太多，那么需要控制并发量，比如说创建一个异步池，超过并发的数量就等待前面完成后再继续。
> 
> 注意：上传切片的时候，需要给切片一个 index 而且必须按照顺序给，因为合并的时候就是按照顺序合并的二进制数据，不然的话文件合并后会出现错误。

```js title="async-pool"
async function asyncPool(poolLimit, array, iteratorFn) {  
  const ret = []; // 存储所有任务的 Promise  const executing = new Set(); // 跟踪正在执行的任务  
  
  for (const item of array) {  
    // 创建任务的 Promise，调用 iteratorFn 执行异步操作  
    const p = Promise.resolve().then(() => iteratorFn(item));  
    ret.push(p); // 将 Promise 存入结果数组  
    executing.add(p); // 添加到执行集合  
  
    // 任务完成后从执行集合中移除  
    const clean = () => executing.delete(p);  
    p.then(clean, clean);  
  
    // 若当前执行数达到限制，等待任意一个任务完成  
    if (executing.size >= poolLimit) {  
      await Promise.race(executing);  
    }  
  }  
  
  // 等待所有任务完成并返回结果  
  return Promise.all(ret);  
}
```
